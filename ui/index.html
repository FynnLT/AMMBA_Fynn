C Preferences & Energy-Type Multipliers

Allocation rules applied by the Clearing Node (Guide §6): (1) mutual preferred partners are served first at the clearing price, (2) the residual is split pro-rata, (3) energy-type multipliers adjust the per-trade rate ex-post. These settings are sent with the trigger and computed in the backend.

Multiplicative: green = p × (1 + green_multiplier × scale), grey = p × (1 − min(grey_levy, levy_cap)); the bonus is scaled down when the levy under-collects, and any over-collection stays with the pool (reported as a surplus).  ·  Additive: the bonus per kWh is the parameter and the levy follows from funding it — zero-sum by construction.  ·  A preferred pair only counts when both sides select each other.

D Run Clearing — backend round-trip

Creates the market and orders in the off-chain DB, then triggers the Clearing Node — exactly the calls the Market Orchestrator would make. Preferred-partner priority and the energy-type multipliers from C are computed by the Clearing Node and returned in the response; the browser only renders them.
